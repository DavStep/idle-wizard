# Top Panel

The top panel is shared room UI. It uses Root Run's qUIck-authored main-HUD composition above every page. Its background uses the active theme's matching top-panel nine-slice: `midnight-top-panel-background.9.png` unchanged for Night and `day-top-panel-background.9.png` for Day. Both are generated from the matching inactive bottom-room-tab skin with `30px` corners baked into a vertical flip, then stretched across the full source width from the top edge. Rebuild them with `node scripts/generate-top-panel-background-assets.mjs`; do not add a second runtime flip. The compact background ends at source y `88`, just below the username and mana-rate labels, leaving a `16px` separation before room content begins at y `104`.

The generated metadata keeps the authored `157px` width as the safe horizontal minimum so the top-panel squircle cannot collapse into a narrow capsule in the UI editor or compatibility checks. Its vertical center may still compress to one pixel, giving a `32px` minimum height.

Keep the source geometry at `1080px` and map it through the shared `/3` retained-Pixi scale: the HUD root starts at authored `32/32` (`10.67/10.67` source), avatar at the far left, level star and rail centered across the top, three equal currency capsules below the rail, and the square settings button at the far right. Do not retain the reference export's authored `108px` notch offset inside Pixi; `canvas.css` already starts the interactive canvas below `safe-area-inset-top` and fills that external strip with the top-panel color. The three capsules are coin, the page-context currency (crystal by default), and mana. Resource icons lead their values. The username is centered directly under the avatar, and the mana generation rate is centered directly under the mana capsule.

Player portraits use the generated square cuts in `assets/game/source/avatars`. Elara is the composition reference: every cut aligns the anatomical face center and eye line, then applies only the small scale correction needed to keep head and hand size consistent. Hats, hair, weapons, shields, quivers, and other decoration may clip. Keep the original `assets/game/source/characters` art unchanged for tutorial and character-scene use. Run `npm run assets:avatars` after adding or retuning a selectable character.

The level rail reuses Root Run's exact level-star, fixed panel, rounded track, and authored yellow fill assets. Thin ticks divide the rail into one segment per configured request; a partially completed active request fills the matching fraction of its segment. Do not render a fraction, remaining count, or other progress number on or under the rail. Keep the whole rail hidden at level 0 and reveal it only after the automatic transition reaches level 1. Completed requests first give the Workshop request rail 260ms to fill and sweep its clipped Root Run shine, then reuse Root Run's one-star research flyout exactly: the retained Pixi path maps its 68px icon, 900px/s speed, and 96px arc through the shared `/3` source scale, holds the rail until arrival, then plays the eight-spark burst and 400ms level-star impact. The next request is revealed on star arrival. The final request fills the old rail before the badge automatically advances and the next level rail appears. Skip this choreography when reduced motion is requested.

The retained-Pixi HUD is the production path. Its rail frame and fill use the copied Root Run qUIck assets, while divider state remains an independent graphics layer. The level star and the complete visible progress rail are one press target that opens Level Rewards, with shared press feedback and tap haptics. Animate the fill's right edge instead of using `scaleX`, which would squash both rounded caps. Shrink resource text only when it would clip. Mana uses the same vivid blue token everywhere.

Open the reproducible non-persistent `1 / 4` review state with `/?devUi=topPanelQuestProgress` or `cheats.openUi('topPanelQuestProgress')`. The preview hides the tutorial backdrop without changing tutorial progress, so native-pixel captures preserve the panel's real colors.

The Level-reward dialog reuses Load Stall's split-paper Expedition composition: no continuous paper panel, two full-width instances of the exact dialog paper nine-slice, the standard dialog content column with no added side inset, an `8px` visible paper-to-paper gap, and fixed yellow previous/next buttons inside the lower board corners. All dialog copy is Title Case. Mana and crystal amounts use their atlas icons after the numeric value while retaining accessible resource labels.

The Workshop Inbox action opens the retained global Inbox, not the legacy generic Workshop row dialog. Each mail record uses the reusable `InboxMailWidget`: one `inner-section-panel-white` message box with its event/message title, sender/date context, wrapped body, reward summary, and a single claim/status area. Claims use the shared green radius-50 regular button and settle visibly to the checkmark plus `Claimed` as soon as the server collection succeeds.

Settings open directly to one light Root Run device board containing the icon-led `sfx`, `music`, `haptics`, and `theme` rows. Each row uses the shared Root Run compact switch. Theme is account-persisted, defaults to Night, and pairs a moon with the off/Night state and a sun with the on/Day state. A separate light Root Run block below it contains the Google account heading, live connection state, and existing connect/disconnect action; connecting always carries the current gameplay persistence save. The real client version and connected user identity follow both blocks, with a yellow copy action next to the shortened identity. The Settings surface has no account, report, configuration, or visual-option tab strip. Username and character customization live in the separately titled `Wizard` surface; its Avatar/Frame controls reuse the shared brown text tabs and its Save action reuses the shared green regular button. Enabled unselected avatar and frame choices reuse the shared compact press animation, touch haptic, and release-confirmed click sound; selected and locked choices stay silent. Feedback entry remains a dedicated contextual surface. Pressing the top-panel avatar opens the Wizard avatar picker directly; locked choices stay muted silhouettes.
